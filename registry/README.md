# Mastery Path course registry and evidence package

The single source of truth for every count published on learnmasterypath.com. Generated by
`tools/registry/build_registry.py` from the live, published site; never edited by hand except the inputs marked ✎.

| File | What it is |
|---|---|
| `config.json` ✎ | Definitions, counting rules and thresholds, technology/professional classification, website registry. Its `methodology_version` is stamped on every audit. |
| `ids.json` | Stable IDs: courses `MP-001…`, lessons `MP-001-0001…`, plus first-publication dates. Append-only; an ID never changes when a title changes. |
| `reviews.json` ✎ | Human content reviews (course_slug, reviewer, date, notes). Reviews recorded in the protected dashboard are merged from `api.learnmasterypath.com/api/reviews`. |
| `ai-review-register.json` | Owner-requested AI-assisted assessment register for all 102 courses; it is separate from `reviews.json` and does not qualify courses as human-reviewed. |
| `record.json` ✎ | Guinness application status. Update only from written Guinness World Records correspondence. |
| `courses.json` | One record per course (schema in the brief: IDs, URLs, classification, dates, counts, eligibility + reasons, check results). |
| `lessons.json` | One record per teaching lesson only (level, module, URL, word count, exercise count, qualification). |
| `projects.json` | One record per project or capstone page, kept apart from lessons (`project_type`, level, URL, word count, practice sections). IDs are page IDs shared with `lessons.json`; they never change. |
| `mastery_path_project_inventory.csv`, `mastery_path_exercise_gaps.csv` | The project inventory as CSV, and the list of lessons that have no exercise (empty when every lesson has one). |
| `summary.json` / `mastery_path_audit_summary.json` | Totals for this audit: registered/published/passed automated checks/qualified, lessons, projects, capstones, exercises, quizzes, categories, paths, domains, failures, duplicates. |
| `course-facts.json` | Small per-course extract used by course pages (`assets/learn.js`). |
| `websites.json` | Website ecosystem registry (owned, subdomain, accounts, external references). |
| `mastery_path_course_inventory.csv` | Master course inventory. |
| `mastery_path_lesson_inventory.csv` | Master lesson inventory. |
| `mastery_path_course_verification_report.csv` | Per-course check results and failure reasons. |
| `mastery_path_duplicate_candidates.csv` | Exact/near-duplicate lessons and similar course titles for human review (nothing is removed automatically). |
| `mastery_path_evidence_register.csv` | Evidence ID, file, collection time, collector, status and SHA-256 for each artefact. |
| `SHA256SUMS` | Checksums of the artefacts (`shasum -a 256 -c SHA256SUMS`). |
| `audits/<audit-id>/` | Archived, unchanged copies of an audit's evidence (`--archive`); `audits/index.json` lists them. Never edit or delete these. |

## Run an audit

```bash
python3 tools/registry/build_registry.py --check-urls [--archive] [--repos ../]   # measure (≈2 min with URL checks)
python3 tools/registry/build_pages.py                                            # catalogue, quality, impact, record pages + numbers in existing pages
python3 tools/registry/test_registry.py                                          # data-integrity tests
```
The GitHub Action "Course registry audit" runs this daily; run it by hand with "archive" before sending evidence.

## Record a human review
Protected dashboard: `https://api.learnmasterypath.com/admin/course-verification` (password = Worker secret `ADMIN_TOKEN`) → "Record review".
Or add an entry to `reviews.json`. The course becomes `qualified` at the next audit; until then it is `passed_automated_checks` (or `needs_fixes` / `rejected`).

## Review packet (for the human reviewer)
`python3 tools/registry/review_packet.py` writes `review-packet.csv`: per course, the automated facts, four sample pages (the first lesson of each level), the capstone and blank check columns. It records nothing; a course only becomes `qualified` after a named person reads it and adds a dated entry to `reviews.json`.

## Check production against the audit
`python3 tools/registry/check_live_sync.py` loads the published `summary.json`, the registry-driven pages and every course home page from learnmasterypath.com and exits 1 if any shows a different audit id or count. `test_registry.py` runs the same comparison on the files in the repository before each commit.
